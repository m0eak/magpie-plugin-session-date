2. 仅 chat system/developer content、responses instructions 和 system/developer input、anthropic 顶层 system、gemini systemInstruction 中的文本。其他 role、不认识字段、图片/tool/thinking/非文本保持。对于缺省 type 的 content block 是否处理以真实合法协议为依据，不把任意对象中的 text 都扫一遍。不做协议转换或跨块拼接。
3. 文本匹配要求 LobeHub `<tools>` / `<tool name="Memory">` 或 `<tool name="Credentials">` 包裹中的 `<tool.instructions>` + `<session_context>`，对真实模板核验 wrapper 属性/标签形式；仅在这些区域删除独立整行英文 Session date: Weekday, Month D, YYYY。允许水平缩进和 LF/CRLF，其他字节与非文本元数据（尤其 cache_control）保持，未匹配请求应返回 undefined。严格避免 user/assistant/tool/result 文本、markdown fenced code、引用行和普通说明中的相同日期。对于同一区域内伪造完全相同结构无法可靠语义区分的限制写清，不宣称绝无误匹配。不得去删 Current date / ISO 日期 / 普通 system prompt 中无 wrapper 的行；不把某个具体日期写死。去掉整行的分隔符须精确、有测试。空块保留，多处命中累加，重复清理幂等，输入对象不就地修改。若 wrapper/tag 跨 block 拆分，跳过而不合并。JSON 无法承诺序列化字节完全相同，要求除实际匹配文本外结构深等。
4. 聚合字段：processedRequests, matchedRequests, removedLines, unmatchedRequests=processedRequests-matchedRequests；UTC startedAt, updatedAt, lastMatchedAt（未命中时 null）。不保存正文、Key、模型、session/agent/provider 明细。支持协议进入 hook 计一次；禁用由宿主插件启停，无额外开关/重置/日统计。Task2 fix1由主代理裁定仅对四协议必要message/input/parts/role/content形状作浅层“可计量”校验，不复制完整上游schema；已知结构畸形不变换/不计数，未知扩展字段透传，未知扩展payload不计数。此限制仅定义统计资格，不扩展Task1过滤器语义。
5. 后续统计约 30 秒异步 flush，不阻塞模型请求，支持同 config 多 host 合并不丢并发计数，原子替换/崩溃一致性/可控锁失败；坏存储 fail-open，只展示存储异常不回显路径/正文。允许突然崩溃损失尚未 flush 增量。最简可靠技术按宿主已用 Bun 运行时确定，可选 Bun 内置 SQLite 事务而非徒手不可靠锁，禁止为了统计安装原生全局依赖；跨进程 exactly-once flush 不应凭空承诺。后续阶段必须先核验真实 host/page.service 生命周期，勿假设同内存。Task2 fix1由主代理裁定：statistics listener启动失败属于非核心部分降级，request hook仍应加载/过滤；状态明示`listener-unavailable`，统计页必须报错，不得伪装正常空数据。此局限不豁免Task3验证真实宿主loader/page生命周期。
6. 页面 phase3：sidebar 插件入口，紧凑信息层级，沿用 page-fingerprint 的留白/布局与宿主 light/dark CSS variables/onTheme；状态、四计数、统计起点/最近命中/更新时间，说明「统计为提示词变换次数，不代表模型缓存命中率」。page/service 仅本地 loopback，宿主代理，不开公网端口，不使用生产 Key、不破坏 CSP/token 校验、不加不必要自定义头。无请求正文/最近请求内容。
7. 删除日期可能弱化 Memory 缺少消息时间戳时的相对时间 fallback，README/页面适量提示。其他动态 prompt/路由/缓存 TTL 仍影响效果。
